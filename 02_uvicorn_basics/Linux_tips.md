# Linux Tips: サーバープロセスの振る舞いを理解する

この章では、`uvicorn` を起動した際に Linux 内部で何が起きているのかを、システム管理者の視点で深掘りします。

---

## 1. フォアグラウンド実行とシグナル

`uvicorn` を起動すると、ターミナルが入力待ちに戻らなくなります。これを **フォアグラウンド (Foreground) 実行** と呼びます。

### Ctrl + C の正体
実行を止める際によく使う `Ctrl + C` は、単なる「停止ボタン」ではありません。
Linux カーネルからプロセスに対して **SIGINT (Signal Interrupt / 割り込み信号)** というメッセージを送っています。

- **仕組み**: `uvicorn` はこの SIGINT を受け取ると、「現在処理中のリクエストを最後まで完了させてから終了する」という **Graceful Shutdown (優雅な停止)** を行います。
- **Tips**: 実務（本番環境）では、サーバーを止める際に「強制終了 (SIGKILL)」ではなく、この「SIGINT」や「SIGTERM」を正しく送ることが重要です。

---

## 2. ネットワークの「待ち受け」とインターフェース

`ss -ltnp` で確認した `127.0.0.1:8000` というアドレスには重要な意味があります。

### 127.0.0.1 (ループバックアドレス)
これは「自分自身」を指す特別な IP アドレスです。Linux の内部で完結する通信であり、外部（他の PC やスマホ）からはアクセスできません。

### 外部に公開する場合
もし演習で「隣の席の人の PC からアクセスしたい」といった場合は、以下のように起動します。
```bash
uvicorn app:app --host 0.0.0.0
```
0.0.0.0: これは「Linux が持つすべてのインターフェース（有線 LAN、Wi-Fi など）で待ち受ける」という指示になります。

### 【重要】学校の演習環境での注意点
`--host 0.0.0.0` を設定しても、学校のネットワーク環境（VLAN分離やネットワーク分離）によっては、隣の席の PC からアクセスできないことがよくあります。

- **理由**: 多くの学校ネットワークでは、学生用 PC 同士が直接通信できないよう「プライバシーセパレーター」などの制限がかかっています。
- **学びのポイント**: 「自分の Linux の設定は正しい（ポートは開いている）が、上位のネットワーク機器（ルーターやスイッチ）で遮断されている」という**ネットワーク階層の切り分け**を意識しましょう。

## 3. 環境変数 PATH と実行ファイルの優先順位
which uvicorn を実行した際、なぜ仮想環境内の uvicorn が選ばれるのかを知ることは、トラブル解決の第一歩です。

### PATH の優先度
Linux はコマンドが入力されると、環境変数 $PATH に登録されているディレクトリを左から順番に探します。

```Bash
#activate 前後の PATH を比較してみる
echo $PATH
```
activate コマンドを実行すると、スクリプトが現在のシェルの $PATH の 最優先位置（一番左） に仮想環境の bin ディレクトリを挿入します。これにより、OS 標準の Python ではなく、プロジェクト専用の Python やライブラリが優先的に使われる仕組みになっています。

## 4. プロセスの親子関係
pstree -p で確認した際、uvicorn は単独で動いているように見えますが、実は親プロセス（シェルなど）から派生しています。
- PID (Process ID): Linux が各プロセスに割り当てる識別番号です。
- PPID (Parent Process ID): そのプロセスを起動した「親」の番号です。

サーバーがフリーズして Ctrl + C が効かない場合、システム管理者はこの PID を特定し、
```bash
kill <PID>
```
コマンドで外側から停止させることになります。
