# Concepts: Logging and Application Log

この章では、FastAPI アプリケーションにおける **ログ（logging）** を通して、  
アプリケーションの内部で「何が起きているか」を記録・観察する方法を学びます。

ログはエラーのためだけのものではありません。  
アプリケーションの振る舞いを **後から説明できる状態にする** ための仕組みです。

---

## ログとは何か

ログとは、

- アプリケーションが
- いつ
- どのような処理を行ったか

を **時系列で記録する情報** です。

重要なのは、ログは  
「その場で見るための出力」ではなく、  
**後から振り返るための記録** であるという点です。

---

## print と logging の違い

最初のデバッグでは `print()` を使うこともありますが、  
print と logging には明確な役割の違いがあります。

| print | logging |
|---|---|
| その場で確認する | 記録として残す |
| 出力先は固定 | 出力先を制御できる |
| 重要度の概念がない | ログレベルがある |
| 本番では使いにくい | 本番運用を前提としている |

この章では、  
**「print の延長として logging を使う」のではなく、  
最初から logging を使う理由**を理解することを目的とします。

---

## ログはどこに出ているのか

基本的な設定では、logging の出力先は **標準出力（stdout）** です。

そのため、

```bash
uvicorn main:app --reload
```
で起動した場合、ログは そのターミナル画面に表示されます。

この時、同じターミナルには次の2種類のログが混ざって表示されます。

- サーバログ（uvicorn が出しているログ）

- アプリケーションログ（自分が書いた logger のログ）

混ざって見えるのは **正常な状態** です。

---
## アクセスログとアプリケーションログ
ログには役割の異なる種類があります。

### アクセスログ
- リクエストが来た事実を記録する

- HTTP メソッド、パス、ステータスコードなど

- 主に サーバー側（uvicorn） が出力する

### アプリケーションログ
- アプリの中で何をしたかを記録する

- 分岐、処理結果、例外など

- 自分が意図して書くログ

アクセスログは「外から見た記録」、
アプリケーションログは「中で起きた記録」と考えると分かりやすいです。

---

## ログレベルという考え方
logging には、情報の性質を表す ログレベル があります。

代表的なものは次の通りです。

- DEBUG：詳細な調査用

- INFO：通常の動作記録

- WARNING：注意が必要な状態

- ERROR：処理に失敗した状態

ログレベルは
「重要度の順位」ではなく、
**用途ごとの分類** だと捉えると理解しやすくなります。

---

## ログはいつ書かれるのか
FastAPI では、

- アプリ起動時

- HTTP リクエストを受け取ったとき

- エンドポイントの処理中

- 例外が発生したとき

など、**任意のタイミング** でログを書くことができます。

重要なのは、

ログは「自動で全部出るもの」ではなく、
**必要な場所に自分で書くもの**

という点です。

---
## この章で意識してほしいこと
^ ログは「デバッグ用の出力」ではない

- ログは「アプリの振る舞いの記録」である

- アクセスログとアプリログは役割が違う

- ログを書くことは、アプリに説明責任を持たせること
