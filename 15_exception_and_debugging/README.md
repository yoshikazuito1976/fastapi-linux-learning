# 15 Exception and Debugging

この章では、FastAPI アプリケーションにおける例外（Exception）とデバッグ（Debugging）を扱います。

アプリケーションは、常に正しく動くとは限りません。
そのため「壊れたときに何が起きているかを説明できること」が重要です。

## この章の目的

- 例外とは何かを理解する
- FastAPI がエラーをどのように扱うかを知る
- デバッグ時の基本的な見方を身につける
- ログと例外の役割の違いを理解する

## この章で扱うこと

- HTTPException を使ったエラー応答
- raise による例外の発生
- デバッグモードでの実行
- スタックトレースの読み方
- Logging と Exception の関係

## 前提条件

- FastAPI の基本的なエンドポイント定義が書けること
- uvicorn でアプリケーションを起動できること
- 14章（Logging and Application Log）を読んでいること

## 実行方法

```bash
uvicorn main:app --reload
```

- `--reload` を付けることで、デバッグ向けの実行になります
- エラー発生時は、ターミナルの出力を必ず確認してください

## この章のポイント

- 例外は「失敗」ではなく「観測された事実」
- エラーは隠すものではなく、記録して理解するもの
- ログは「内部向け」、例外は「外部向け」

## ゴール

- エラーが出ても慌てず、原因を追えるようになる
- 例外とログを分けて考えられるようになる
- FastAPI のエラーハンドリングの基本を説明できる

## 補足

この章では、**すべてのエラーを完璧に処理すること**は目的にしていません。

まずは、

1. 例外が起きる
2. 表示される
3. 読める

この流れを体験することを重視します。
